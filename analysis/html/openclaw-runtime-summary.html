1. OpenClaw Runtime 的部署形态

OpenClaw Gateway 是同一个运行时，只是可以运行在不同载体中：

OpenClaw Runtime
├─ 原生进程（Linux / macOS / Windows）
├─ WSL2 载体（Windows Hub 管理本地 WSL Gateway）
├─ Docker / OCI 容器（本地或云端）
├─ 云端主机（VPS / 云 VM / 容器 / K8s）
└─ 桌面应用内嵌（LobsterAI 使用本地 Windows runtime）

WSL、Docker、云端都是部署环境的选择，不是三套不同的 Runtime。

2. LobsterAI 为什么使用本地 Gateway

LobsterAI 是桌面产品，默认“装完即用”。本地 Gateway 有利于：

  • 开箱即用，不需要用户部署服务器。
  • 数据本地保存，隐私更可控。
  • loopback 连接，延迟低，可离线。
  • 与 SQLite、IM、MCP、Skill、Scheduled Task、Browser 深度集成。
  • 本地 token proxy、配置同步、模型路由更简单。

LobsterAI 并没有重写 Gateway，而是把同一个 OpenClaw Runtime 打包进本地，并自己管理它的进程、配置、端口和 token。

3. 为什么不使用原生 WSL

  • 避免 WSL2 和虚拟化依赖，安装更小、兼容性更简单。
  • Windows 原生 Node/Electron 启动，生命周期和打包更可控。
  • 直接使用 Windows 文件系统、浏览器、进程等原生能力。
  • 更利于安装器、自动更新、runtime 修复和 patch 管理。

4. Gateway 能否部署到云端

可以。官方推荐把 Gateway 放在常开主机上，例如 VPS、云服务器、Mac mini、树莓派。常见连接方式：

  • SSH 隧道：ssh -N -L 18789:127.0.0.1:18789 user@vps
  • Tailscale / VPN
  • Cloudflare Access 或可信反向代理
  • wss:// + TLS 公网入口

5. Gateway 能否 Docker 部署

可以，官方提供 Dockerfile、docker-compose.yml 和 scripts/docker/setup.sh。

docker compose up -d openclaw-gateway
docker compose logs -f openclaw-gateway
curl http://127.0.0.1:18789/healthz

需要持久化的目录：

OPENCLAW_CONFIG_DIR
OPENCLAW_WORKSPACE_DIR
OPENCLAW_AUTH_PROFILE_SECRET_DIR

安全上不要直接暴露 18789，应使用 SSH、Tailscale、Cloudflare 或反向代理 + TLS。

6. 阿里云 Docker Gateway 配置清单

  1. 安全组只开放 22 和 443，不开放 18789。
  2. Docker 端口只绑定 127.0.0.1:18789:18789。
  3. 设置 OPENCLAW_GATEWAY_TOKEN、OPENCLAW_GATEWAY_BIND=lan、OPENCLAW_TZ=Asia/Shanghai。
  4. 持久化 config、workspace、auth-profile-secrets。
  5. 完成 onboarding，配置模型 provider。
  6. 配置 Telegram / Discord 等渠道。
  7. 验证 /healthz、/startupz、/readyz。
  8. 客户端通过 SSH、Tailscale 或 wss:// 连接。
  9. 配置备份和升级流程。

7. WebSocket 使用场景与通信

WebSocket 适合长连接、双向推送、流式数据和低延迟场景。

场景说明
Gateway 控制面客户端连接 Gateway，发送请求、接收事件
LLM 流式输出token、message、tool call 事件持续推送
权限审批Gateway 推送 approval，客户端回传 allow/deny
工具执行shell、browser、MCP 状态和结果推送
实时语音ASR / Talk 实时音频会话
浏览器自动化Chrome DevTools Protocol WebSocket

OpenClaw Gateway 使用 JSON 帧通信：

请求：{ "type": "req", "id": "req-1", "method": "chat.send", "params": {} }
响应：{ "type": "res", "id": "req-1", "ok": true, "payload": {} }
事件：{ "type": "event", "event": "message", "payload": {} }

最小 WebSocket 服务端

import { WebSocketServer } from 'ws';

const wss = new WebSocketServer({ port: 18789 });

wss.on('connection', (socket) => {
  socket.on('message', (data) => {
    const msg = JSON.parse(data.toString());
    if (msg.type === 'req') {
      socket.send(JSON.stringify({
        type: 'res',
        id: msg.id,
        ok: true,
        payload: { status: 'running' },
      }));
    }
  });
});

最小 WebSocket 客户端

import WebSocket from 'ws';

const ws = new WebSocket('ws://127.0.0.1:18789');

ws.on('open', () => {
  ws.send(JSON.stringify({
    type: 'req',
    id: 'req-1',
    method: 'gateway.status',
    params: {},
  }));
});

ws.on('message', (data) => {
  console.log(JSON.parse(data.toString()));
});
