Final Agent Security Architecture

1. 目标链

Intent -> Context -> LLM -> Tool -> Process -> File -> Network

2. 如何在 LobsterAI 中实现可观测

User-space Sensor

插入 Renderer prompt submit 和 coworkService.startSession/continueSession，捕获用户原始意图。

Electron Sensor

插入 preload 与 ipcMain，捕获 UI 事件、权限、会话生命周期。

Agent Runtime Sensor

插入 CoworkEngineRouter、OpenClawRuntimeAdapter，捕获 message、sessionStatus、contextUsage、gateway runId。

Tool Sensor

插入 openclawApprovalBridge 和 OpenClaw agent-tools.before-tool-call，捕获 tool name、参数、approval 决策。

Node.js Sensor

插入 OpenClawEngineManager、bash-process-registry、child_process 调用点，捕获进程 spawn/env/cwd。

OS Sensor

使用 ETW、Windows Process/File/Network 监控、minifilter、audit 捕获系统事件。

Kernel Sensor

使用驱动/ETW Kernel 事件，捕获更底层的 file/network/process 操作；绕过风险更低但复杂度更高。

3. 各层对比

层级可见性精确性性能稳定性绕过风险推荐
User-space中高高高高高
Electron中高高高中高
Agent Runtime高高中中中高
Tool高高中中中高
Node.js中高中中中中
OS高中中高低高
Kernel高中低中最低中

4. 推荐部署层级

Agent Runtime Sensor + Tool Sensor + OS Sensor 三层组合，能在性能与可见性之间取得平衡。

5. 与 Chacha Runtime 的衔接

先在 LobsterAI 侧建立 agentTraceId 和 identity chain，再把 OS 事件按 processId/file/network + timestamp 关联，形成 Correlator 输入。
