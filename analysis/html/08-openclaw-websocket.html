Phase 09 — OpenClaw WebSocket Protocol

1. 功能

分析 LobsterAI 作为 operator 客户端与 OpenClaw Gateway 的 WebSocket 协议。

2. 协议源码位置

关注点文件
客户端门面D:\hf\L\openclaw\src\gateway\client.ts
共享客户端D:\hf\L\openclaw\packages\gateway-client\src\index.js

协议包D:\hf\L\openclaw\packages\gateway-protocol\src\index.js

3. 连接阶段

[源码已确认] LobsterAI 创建客户端时传入：

url, token, clientDisplayName, clientVersion,
mode: 'backend', role: 'operator',
scopes: ['operator.admin'], deviceIdentity: null

证据：src/main/libs/agentEngine/openclawRuntimeAdapter.ts:6164-6176。

[源码已确认] 服务端 handler 负责 pre-auth 限制、handshake auth、presence 和 message-handler attachment。

证据：openclaw/src/gateway/server/ws-connection.ts:169。

4. Request / Response 帧

[源码已确认] 认证后请求分发只接受 request frame：

if (!validateRequestFrame(parsed)) { ... }

证据：authenticated-request-dispatch.ts:67-75。

[源码已确认] 响应帧结构：

send({ type: "res", id: req.id, ok, payload, error })

证据：authenticated-request-dispatch.ts:118。

[源码已确认] 错误形状：

  • INVALID_REQUEST
  • UNAVAILABLE
  • errorShape(code, message)

证据：authenticated-request-dispatch.ts。

5. 事件帧

[源码已确认] Gateway 可向客户端广播事件；服务端有 broadcast(event, payload) 抽象。

[推测，待进一步验证] 事件帧的具体 schema 应在 packages/gateway-protocol 中读取，本阶段只确认 request/response 骨架。

6. 重连语义

[源码已确认] 客户端有 reconnect 状态：

  • gatewayReconnectTimer
  • gatewayReconnectAttempt
  • gatewayStoppingIntentionally
  • gatewayReconnectSuppressed

证据：openclawRuntimeAdapter.ts:2601-2605。

[源码已确认] 服务端有 keepalive：

  • startWebSocketKeepalive：ws-connection.ts

7. 时序图

sequenceDiagram
  participant L as LobsterAI Adapter
  participant C as GatewayClient
  participant S as Gateway WS Server
  L->>C: new GatewayClient(url, token, role, scopes)
  C->>S: connect + handshake/auth
  S-->>C: hello / auth ok
  C-->>L: onHelloOk
  L->>C: request(method, params)
  C->>S: req {type,method,id,params}
  S-->>C: res {type:"res",id,ok,payload,error}
  S-->>C: event broadcast
  C-->>L: event callback

8. 学习重点

  • Gateway 协议是请求/响应 + 事件广播的混合协议。
  • 认证发生在 pre-auth 阶段；认证后帧才进入方法分发。
  • 角色/scope 决定方法可用性，operator.admin 是高权限角色。
