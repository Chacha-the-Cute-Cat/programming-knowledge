Phase 06 — Electron IPC

1. 功能

分析 Renderer / Preload / Main 三端的通信模式。

2. 通信模式

[源码已确认] 存在以下模式：

模式机制
请求/响应ipcRenderer.invoke + ipcMain.handle
单向发送ipcRenderer.send + ipcMain.on
主动推送ipcRenderer.on / webContents.send
流式推送api:stream:、CoworkIpcChannel.Stream

5. 数据方向

Renderer
  -> window.electron.*
  -> preload
  -> ipcRenderer.invoke/send
  -> ipcMain.handle/on
  -> Main service
  -> store / OpenClaw / IM / MCP / OS

6. 流式通信

[源码已确认] src/main/preload.ts:257-296 暴露：

  • api:fetch
  • api:stream
  • api:stream:cancel
  • api:stream:<requestId>:data
  • api:stream:<requestId>:done
  • api:stream:<requestId>:error
  • api:stream:<requestId>:abort

7. 学习重点

  • channel 常量是跨进程契约，需优先阅读 src/shared/*/constants.ts。
  • 请求/响应用于低频命令；流式事件用于 token、tool、permission、engine status。

8. 如果让我重新设计

为 IPC 增加统一 envelope：

{ requestId, channel, payload, ts, error? }

并显式定义 timeout、cancellation、serialization 上限，避免多套临时协议。
