Phase 05 — Preload 与安全边界

1. 功能

Preload 是 Renderer 与 Main 之间的受控桥。Renderer 不能访问 Node.js，只能通过 preload 暴露的 API 进入 Main。

2. 源码位置

Preload文件用途
主 preloadsrc/main/preload.tswindow.electron
浏览器标注src/main/browserAnnotationPreload.tswebview 标注
凭据登录src/main/browserCredentials/agentBrowserCredentialPreload.ts隔离登录
手动凭据捕获src/main/browserCredentials/manualCredentialCapturePreload.ts手动捕获
Passkeysrc/main/browserPasskeys/passkeyPreload.tsWebAuthn/passkey

3. 主 preload API

[源码已确认] src/main/preload.ts:140：

contextBridge.exposeInMainWorld('electron', { ... })

4. 安全配置

[源码已确认] src/main/main.ts:13885-13899：

nodeIntegration: false
contextIsolation: true
sandbox: true
webSecurity: true
webviewTag: true

5. 关键结论

[源码已确认] Renderer 不能直接访问 fs、child_process、process。

[源码已确认] 敏感能力通过 ipcRenderer.invoke 由 Main 执行。

[源码已确认] 凭据 preload 是独立隔离面，用于在 sandbox 页面中填充账号但不把密码交给 Agent。

6. 安全分析

  • webviewTag: true 增加了 webview 攻击面，需要审核 webview 页面和 guest preload。
  • sandbox: true 是默认值，但 webview 内部是否 sandbox 取决于具体 webview 配置。
  • 所有 IPC channel 应使用 src/shared/*/constants.ts 常量，避免字符串漂移。

7. 如果让我重新设计

为 window.electron 增加类型化 schema 和参数运行时校验；对高频流式事件提供背压和取消控制，避免 Renderer 被事件淹没。
