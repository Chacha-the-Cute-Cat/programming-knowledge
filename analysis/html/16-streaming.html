Phase 18 — Streaming

1. 功能

追踪 LLM 输出如何从 Provider 流到 Renderer UI。

2. 链路

LLM Provider
  -> OpenClaw runtime (SSE/stream)
  -> Gateway event
  -> GatewayClient
  -> OpenClawRuntimeAdapter
  -> CoworkEngineRouter events
  -> Main IPC / webContents.send
  -> Preload
  -> Renderer Redux
  -> React Chat UI

3. LobsterAI 侧证据

[源码已确认] Adapter 暴露 Cowork stream 事件：

  • message
  • messageUpdate
  • sessionStatus
  • contextUsageUpdate
  • contextMaintenance

证据：coworkEngineRouter.ts 的 bindRuntimeEvents。

[源码已确认] Preload 暴露流式 API：

  • api:stream
  • api:stream:<requestId>:data
  • api:stream:<requestId>:done
  • api:stream:<requestId>:error
  • api:stream:<requestId>:abort

证据：src/main/preload.ts:257-296。

[源码已确认] Renderer 服务：

  • src/renderer/services/cowork.ts
  • src/renderer/store/slices/coworkSlice.ts

4. OpenClaw 侧证据

[源码已确认] 存在：

  • openclaw/src/channels/streaming.ts
  • openclaw/src/worker/inference-stream.runtime.ts
  • openclaw/src/llm/providers/stream-wrappers/
  • openclaw/src/channels/progress-draft-compositor.ts

5. 事件类型

[推测，待进一步验证] token delta、message update、tool call delta、tool result、thinking delta 等由 OpenClaw gateway 事件承载，具体 schema 在 gateway-protocol。

6. 学习重点

  • 流式数据经过四层：Provider、Gateway、Adapter/IPC、React。
  • 每层都可能引入延迟和序列化成本，需要背压和取消。
